# Native fault-test acceptance and evidence limits

This is an acceptance plan, not a test result. A case remains **NOT RUN** until a retained Windows/MT5 run identifies its exact source and harness hashes, compiler log, executable hash, case output and observed state. Earlier MetaEditor compilation proves compilation of the recorded source only; it does not execute these cases. Keep the original 35 EA inputs, approved risk policies, tester-only boundary, unconditional new-entry lock, unknown-future-cost gate and independent budget veto unchanged.

## Evidence classes

| Class | What must actually execute | Permitted conclusion |
|---|---|---|
| NATIVE-PURE | Compiled production MQL function with explicit scalar/structure inputs; no rewritten Python equivalent | That function returned the recorded result for those inputs in that MQL runtime. |
| NATIVE-FILE | Production serialization/parser/reload functions and real MT5 `FileOpen`, write, flush, read and move operations in an isolated sandbox | Actual file behavior for the recorded process and injected fault; not hardware power-loss durability. |
| NATIVE-MOCKSTATE | Production MQL decision functions with named test doubles for clock, symbol, account, history, position, trade result or terminal flags | MQL branch behavior under the declared synthetic state; not a genuine broker fill, account restart or server response. Real FileIO within such a case must be identified separately. |
| REFERENCE / SOURCE | Python policy examples, mocked Python API, or selected source assertions | Reference-policy or source-wiring evidence only; never native MQL execution. |
| BROKER / HISTORY | Actual authorized MT5 tester/custom-symbol run with recorded symbol contract, available history, costs and clock; broker-specific scenarios additionally require corresponding broker evidence | Only the demonstrated execution/data scenario. These remain NOT RUN unless independently evidenced. |

Each case must list every replaced dependency. A production function called through a harness does not make its mocked account/history/clock real. A harness that copies/reimplements its body is a reference test unless byte-equivalent extraction and source mapping are retained. Calling a low-level helper directly does not prove `OnInit`, `OnTick`, `OpenPosition` or `CloseAll` traversed that helper in the production lifecycle.

The harness must expose no route to send actual orders. Replacing the trade transport with a recording/rejecting double is acceptable only in the test program; record its invocation count. Do not change production execution locks to make a test reach a branch. A false entry lock and zero orders demonstrate containment, not signal quality, profitability, stop effectiveness or a strategy backtest.

## Preconditions and retained evidence

- Use a unique synthetic test scope and dedicated directory per independent case; copy deliberately retained state only for the restart cases. Never delete/reset a production or previously halted scope to obtain a pass. `FILE_COMMON` macro fixtures need a unique controlled test path and byte-for-byte preservation of any prior file.
- Record Windows, MetaEditor/MT5 builds; source commit and SHA256 for the EA, `ResearchLifecycle.mqh`, harness and dependencies; generated EX5 hash; compile time and original compiler log. A changed harness/source requires its own compile evidence.
- Record case ID, evidence class, mock list, clock values/timezone, fixture hashes, expected and actual return/status, relevant before/after globals, persisted bytes/hashes, and transport-call counts. Do not publish credentials or personal account identifiers.
- Start from an explicit valid control and mutate one condition. Boundary cases must use the same frozen clock, not wall-clock sleeps. Missing evidence, an unexecuted script, compile failure, timeout or truncated case output is ERROR/NOT RUN, never PASS. A negative case passes only when the exact expected rejection and retained-state invariant are observed.
- Give each mutation its own subcase ID and expected failing function. For journal semantic-field tests, recompute a correct checksum after the controlled mutation; otherwise an early checksum rejection does not demonstrate the later semantic check. Retain a distinct bad-checksum case. Avoid an earlier stale macro field masking the intended calendar-expiry branch.
- Preserve raw case output and process logs, the manifest of expected versus executed IDs, aggregate pass/fail/error/skipped counts, and relevant sandbox snapshots before cleanup. Every requested case omitted from execution is reported separately. A process exit code or summary count alone is insufficient.

## Persistence, restart and idempotency cases

| ID | Production function and trigger | Required observation | Minimum evidence class |
|---|---|---|---|
| J01 | `PublishRecord`, `ReadOneRecord`, `SaveExecutionJournal`: valid empty synthetic journal | Exact round trip, valid checksum and retained consumed-bar/basket fields; final file equals intended record. A nonempty extra record is rejected by `ReadOneRecord`. | NATIVE-FILE |
| J02 | `LoadExecutionJournal`: alter checksum, key, field count, tuple count, duplicate member ID/order, numeric field or append a nonempty line | Returns false; `g_journalHealthy` stays false; damaged file is not rewritten/rebased as fresh state; no trade call. | NATIVE-FILE, plus mock account/history if supplied |
| J03 | `LoadExecutionJournal`: initialized marker but missing journal; journal without marker; old AG2 scope not fresh and no execution journal; leftover `.execution.tmp` / `.execution.started.tmp` | Reject initialization, leave evidence intact, no silent migration/reset. | J04 | `PrepareIntent("OPEN",...)`, then reload persisted unresolved OPEN; repeat for CLOSE | Prepared intent is present on disk before simulated transport. `LoadExecutionJournal` rejects unresolved intent, calls halt latch and never resends/clears it; valid halt/state writes observed where storage is available. Reloading globals alone is not a process restart. | NATIVE-FILE + NATIVE-MOCKSTATE history/account; separate-process run needed for process-restart claim |
| J05 | `ScopedPendingOrders`, `LoadExecutionJournal`: synthetic pending scoped order or unreadable order identity | Order enumeration fails closed; load rejects/latches where reached, even if persisted intent is NONE. A synthetic pending order is not evidence of server-side pending-order recovery. | NATIVE-MOCKSTATE |
| J06 | Valid `PrepareIntent("OPEN",...)` with bar B; reinitialize retained journal then request B, older B-1, and later B+1 | After safe synthetic resolution, B/B-1 return false without changing consumed identity or invoking transport. A later bar may pass only all existing ledger/state gates; it does not authorize an order or erase an unresolved intent. | NATIVE-FILE + NATIVE-MOCKSTATE clock/series/history |
| J07 | `PublishRecord`, `SaveExecutionJournal`, `PrepareIntent`: deny/open-lock staging or destination so actual write/move/readback fails | Return false; failed pre-send persistence makes journal unhealthy and attempts persistent halt; no transport call. Retain the exact injected OS/file error and files. A mocked false write is not real FileIO fault evidence. | NATIVE-FILE |
| J08 | `InitRiskState`, `LatchRiskHalt`, `UpdateDay`: valid halted state/restart/day rollover; missing initialized state; orphan temporary; backward clock | Latch survives retained-state reload/rollover; initialized missing/corrupt state rejects; old-day breach is checked before baseline update. Recovery of equity does not reset halt. Actual process termination and storage fault testing are separate. | NATIVE-FILE + NATIVE-MOCKSTATE account/clock |

`LoadExecutionJournal` sets journal health false on entry; many parse failures simply return false without calling `LatchRiskHalt`. Acceptance must not falsely require a newly written halt barrier for every malformed-file branch. The failure to initialize and no-send outcome are mandatory. Pending-intent/pending-order branches explicitly latch. If all writes fail, the code cannot prove that a new halt survives host loss.

## Exit conditions and remaining gates

Present results by evidence class and individual case ID. Count an assertion, scenario, process restart and broker fill separately; do not inflate a case total by calling each assertion an independent fault simulation. If a narrower native harness covers only scalar/parser/FileIO cases, explicitly list all account/history/fill cases above as NOT RUN rather than extrapolating coverage.

Even a fully passing synthetic native suite does not establish broker SL placement, actual slippage/partial-fill handling, complete broker history, verified future costs, cross-machine filesystem behavior, abrupt-power-loss durability, real macro provenance, live JSON protocol parity or strategy performance. Source checks and Python reference tests remain useful separate evidence. A newly compiled native test binary must not inherit the successful compile status of an older production EX5.

Preparing historical data/configuration is permitted without unlocking entries. Preserve source/license/version, availability times, UTC/server offset and DST, symbol contract, bid/ask tick quality, commissions/swaps and predeclared chronological train/validation/holdout periods. No current CSV or current online model may be represented as historical point-in-time evidence. Report a hard-lock zero-order run as a containment/smoke run only; report performance as NOT RUN until separately authorized prerequisites, costs and execution evidence exist.
